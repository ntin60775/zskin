# zskin — live theming loader для официального ZCode

Лоадер запускает штатный бинарник ZCode с `--remote-debugging-port` и по CDP
вставляет CSS как `<style id="zskin-style">` в рендерер главного окна.
Файлы продукта не изменяются, авторизация и учёт квот не затрагиваются.

## Как применять

1. Тема — обычный CSS-файл. Свои темы держать в репо плагина `themes/`
   или в `~/.config/zskin/themes/`.
2. Запуск с темой (запускает клиент + инжект):

   ```bash
   python3 loader/zskin.py run --theme themes/example.css
   ```

3. Уже запущенный клиент (клиент должен быть стартован лоадером):

   ```bash
   python3 loader/zskin.py inject --theme themes/example.css
   ```

4. Посмотреть цели CDP: `python3 loader/zskin.py list`.

## Ограничения (не терять)

- Инжект живёт, пока жив рендерер: перезапуск окна/клиента = повторный
  `run`. Перезагрузка страницы тоже сбрасывает `<style>`.
- Работает только по клиенту, запущенному с дебаг-портом. Обычный запуск
  без лоадера порт не открывает.
- Селекторы тестируются по факту: DOM рендерера не публичный контракт
  ZCode и меняется между версиями; тема = гипотеза, проверка — глазами
  в работающем клиенте.

## Границы (не переступать)

- Не модифицировать файлы продукта (`/opt/ZCode/**`) — только флаг запуска
  и CSS поверх DOM.
- Не трогать через CDP ничего, кроме презентационного DOM: ни
  `Runtime.evaluate` для обхода подтверждений, ни перехват сети/запросов,
  ни учётные механизмы. Ровно в этих границах способ остаётся
  юридически чистым (см. README, раздел «Границы»).
