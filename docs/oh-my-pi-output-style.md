# Визуальный язык вывода oh-my-pi — формализация

Зафиксировано 2026-10-21. Предмет — как omp оформляет вывод в чат: карточки
инструментов, заголовки, таблицы, инлайн-разметку, подсветку кода, движение
и контраст. Эталон — скриншот сессии omp от 2026-10-15 («Итог всей саги»):
пользователь считает этот вывод образцом. Документ готовит наложение стиля на
[components-join.md](components-join.md) (раздел 12).

Смежные доки: палитра и её перенос в CSS — [theme-spec.md](theme-spec.md);
каталоги компонентов — [zcode-ui-components.md](zcode-ui-components.md) и
[oh-my-pi-tui-components.md](oh-my-pi-tui-components.md).

## 1. Цепочка цвета: кто что решает

Тема omp задаёт hex-роли и красит текст **truecolor-SGR** (`COLORTERM=truecolor`):
экранный цвет окрашенного текста = hex темы, kitty-палитра не участвует.
Kitty-палитра (Gruvbox Dark Soft) отвечает только за **неокрашенное**:
дефолтный fg `#d5c4a1` и дефолтный bg `#32302f`.

Следствие, подтверждённое замером скриншота: **эффективный фон чата —
`#32302f` (kitty soft), а не `bg0 #282828` темы**. Фоновых слоёв три:

| Слой | Hex | Что лежит |
|---|---|---|
| База чата | `#32302f` | проза, таблицы, фон всего транскрипта |
| Тёмная плашка | `#1d2021` | карточка завершённого инструмента, сообщение пользователя |
| Аварийная плашка | `#3c2021` | карточка с ошибкой |

Карточки **темнее** базы — инверсия привычной «карточка светлее». Ошибка
краснее базы, ожидание — вровень с ней (`toolPendingBg #32302f`).

## 3. Типографика

- Одна гарнитура на всё: JetBrainsMono Nerd Font Mono, 13 pt (≈ 17 px).
  Mono-вариант Nerd Font лигатур не содержит; в kitty вдобавок
  `disable_ligatures cursor` — выключены на строке под курсором.
  Проза, код, таблицы, заголовки — mono; смена кегля
  только через OSC 66 (раздел 6), смена гарнитуры — никогда.
- Модификаторы: bold (SGR 1), italic, underline, strikethrough — без дублей
  цветом: жирное не ярче, курсив не серее.
- Разделитель мет — « · » (`sep.dot`), обрамление мет — `(...)`.
- Длительность (`formatDuration`): `283ms` → `12.3s` → `1m 20s` → часы;
  ноль — `0ms`.
- `tui.tight: true` — карточки без горизонтального паддинга (paddingX 0),
  контент вплотную к рамке с зазором в 1 клетку.
- Пунктуация интерфейса: скобки бейджей `[...]`, крестики деревьев `└─`, `├─`,
  эллипсис обрезки `…`.

## 4. Архитектура ответа

Эталонный ритм хода: **проза → карточка(и) вызова → проза → H1 → проза →
таблица → проза**. Правила:

1. Ход открывается прозой без шапки и приветствий.
2. Каждое действие озаглавлено человеческим намерением: при
   `tools.intentTracing: true` (дефолт; в конфиге не переопределён) схема
   каждого инструмента получает аргумент `i` (intent), он становится
   заголовком карточки («Сохраняю финальное решение в память»), из дерева
   аргументов ключ `i` скрыт (`INTENT_FIELD` в `wire`, `HIDDEN_ARG_KEYS`
   в `tools/json-tree.ts`), в eval-ядро аргумент не передаётся
   (`task/eval-tools.ts`).
3. Итоговый блок выделяется заголовком-сценой и сравнительной таблицей;
   после — проза с бонусами и хвостами, без повторов таблицы.
4. Между блоками одна пустая строка (space-токены); плотнее — только внутри
   карточек.

## 5. Карточка инструмента

Геометрия (`render/output-block.ts`): скруглённый бокс `╭ ╮ ╰ ╯`, линия — `─`,
вертикали — `│`, секционные разделители — `├ ┤`; ширина — во всю строку;
контент с паддингом 1; рамка одинарная.

**Главный принцип: активная карточка кричит, завершённая гаснет.**

| Фаза | Рамка | Фон |
|---|---|---|
| running / pending | accent `#fe8019` | `#32302f` (вровень с базой) |
| success | dim `#7c6f64` | `#1d2021` (темнее базы) |
| error | error `#fb4934` | `#3c2021` |
| warning | warning `#fabd2f` | `#32302f` |

Анатомия сверху вниз (на примере скриншота — код-ячейка eval,
`render/code-cell.ts`):

1. **Титул врезан в верхнюю линию**: `╭─── <иконка языка> • <Заголовок> · (283ms) ───╮`
   (угол + три клетки линии + пробел + подпись + заливка остатка линии).
   Заголовок — intent. Иконка языка — Nerd Font-глиф в брендовый цвет языка
   (`LANG_BRAND_COLORS`: Python `#3776ab` — он в эталоне, JS `#f7df1e`,
   Ruby `#cc342d`, Julia `#9558b2`; прочие языки — muted). Маркер статуса —
   `•` (`status.done`, в unicode- и nerd-пресетах; success-зелёный `#b8bb26`,
   подтверждено замером); пока вызов идёт — кадр спиннера (braille/nerd,
   без окраски). Мета длительности — dim. Цвет титула — роль `toolTitle`
   (в теме `""` → `ESC[39m`, дефолтный fg kitty `#d5c4a1`; проверено кодом
   `fgAnsi` и замером); у статусных карточек через `renderStatusLine` —
   accent, описание — muted, бейдж — `[label]` в своём цвете.
2. **Тело**: подсвеченный код вызова; номера строк в dim-гуттере при наличии.
3. **Секции с подписью в линии**: `├── Output ───┤`. Текст вывода —
   `toolOutput` gray; дерево статусов — `└─ <icon> <имя>` с dim-коннекторами и
   muted-иконкой/именем (`tools/eval.ts`: `icon.file` и др.).
4. **Обрезка**: `… N more lines` dim + подсказка раскрытия; у кода — хвост
   потока с «… N earlier lines» сверху.
5. **footerMeta** вшивается в нижнюю линию (`╰── Wall 0.16s · Timeout 300s ──╯`),
   не влезает — переносится в тело над чистой рамкой.

Plain-вариант (`plainToolCard`): без рамки и фона — так рендерятся, например,
markdown-результаты MCP; framed-карточки не должны конкурировать с «легаси»
рамками (свойство `borderColor` глушит фазовый цвет).

Фон строки перекрашивается целиком с защитой от SGR-сбросов внутри контента
(`renderOutputBlock` стабилизирует `\x1b[0m` повторным открытием bg).

## 6. Заголовки markdown

Роль `mdHeading` — жёлтый `#fabd2f`; уровни различаются формой
(`components/markdown.ts:3798`):

| Уровень | Форма |
|---|---|
| H1 | **bold + underline + двойная высота** (OSC 66 `s=2`, kitty-only) + резерв пустой строки под второй ряд глифов + отбивка |
| H2 | bold |
| H3+ | bold **с видимыми решётками** `### Текст` |

OSC 66 (`utils.ts: encodeTextSized`): `ESC]66;s=<1..3>[:w=…][:v=…][:h=…];текст ESC\`,
включается `tui.textSizing: true`, детектится пробой терминала
(`TERMINAL.textSizing`; kitty поддерживает с 0.40 — протокол «Multiple sized
text»). Без поддержки — тот же стиль в одну строку. Заголовок нельзя
переносить и подкладывать фон — строки OSC 66 выводятся raw (обход паддингов
и bg-заливки).

## 7. Таблицы

(`#renderTable` в `components/markdown.ts`.)

- Квадратный грид (`boxSharp`): `┌ ─ ┬ ┐ │ ├ ┼ ┤ └ ┴ ┘` — углы прямые,
  контраст со скруглёнными карточками (у карточек `├ ┤` тоже из `boxSharp`:
  скруглённых «тройников» в Unicode нет).
- Границы **не тонированы** — дефолтный fg `#d5c4a1` (проверено замером:
  линии в скриншоте `#d5c4a1`).
- Шапка — bold, те же рамки; разделитель `├─┼┤` после **каждой** строки,
  не только после шапки.
- Ширины: натуральная по контенту, усадка при переполнении с весами по
  длиннейшему слову (не разрывать слова короче 30 клеток), перенос по словам
  внутри ячеек, выравнивание влево.
- Во время стриминга растущая ячейка держит высоту строки и рисует `…`.

## 8. Инлайн-элементы

- `` `код` `` — фиолетовый `#d3869b`, **без подложки** (отличие от ZCode, где
  инлайн-код на плашке `#3c3836`).
- Ссылка — aqua `#8ec07c` + underline + OSC 8 (кликабельно в kitty). Если
  текст ссылки совпадает с href, URL не дублируется; иначе справа в скобках
  печатается адрес цветом `mdLinkUrl` `#7c6f64`.
- Списки: маркер источника (`- ` / `1. `) окрашен accent `#fe8019`; висячий
  отступ по ширине маркера (`10. ` — 4 клетки); вложенность — 2 пробела.
- Цитата: текст `mdQuote` gray, граница `mdQuoteBorder` bg2.
- hr: `hrChar` × min(ширина, 80) в bg2.
- **Hex-свотчи**: `#RGB/#RRGGBB/#RRGGBBAA` в прозе и коде (не приклеенные к
  словам; в прозе 3-значные — только с буквой a–f, чтобы `#123` не свотчился)
  рисуются как `■` (глиф `md.colorSwatch`; в ASCII-пресете `[]`) цвета
  + сам `#hex` на подложке этого цвета с fg по правилу
  YIQ (≥ 128 → чёрный, иначе белый — правило VS Code). Так «KDE #499144» в
  эталоне превратилось в зелёный чип `#499144` с белым текстом — это не
  карточка issue, а свотч совпавшего hex.
- Сообщение пользователя — плашка `#1d2021` с отступом 1 по бокам, пустой
  строкой сверху и magic-keyword подсветкой (`chat/user-message.ts`).

## 9. Код-блоки и подсветка

- Markdown-fence: линии ` ```lang ` и ` ``` ` красятся в bg2 `#504945`, тело —
  fg1 `#ebdbb2`, отступ `codeBlockIndent`; mermaid — ASCII-арт по ширине.
- Подсветка — нативный syntect (Rust FFI, `@oh-my-pi/pi-natives`; по README

## 10. Движение

- Спиннеры: анимация — кадры braille/nerd без окраски (`SPINNER_FRAMES`,
  8–12 кадров на цикл); статичный глиф статуса — в своём цвете (`status.*`:
  ✔ ✘ ⚠ ⓘ ⏳ ⟳ в unicode-пресете, Nerd Font-глифы в nerd; «•» для done
  в обоих, success-зелёный).
- **Shimmer `kitt`** (`theme/shimmer.ts`): сканер «Рыцарь дорог» — голова ±0,6
  клетки, хвост 7 клеток, скорость 30 клеток/с (не больше 1 клетки за кадр при 30 fps);
  палитра по интенсивности: dim → muted → **accent + bold** на кресте.
- Прогрессбары, счётчики `MetricRow` — вне эталона, роли те же.

## 12. Наложение на components-join.md

Пары по нумерации join-таблицы; «перенос» — что класть в
`themes/gruvbox.css` поверх токенов из theme-spec.md. Поэлементная
нарезка задач по всем 97 парам — [plans/00-common.md](plans/00-common.md). Классы и data-хуки
в колонке «Перенос» — гипотезы: в 3.16.2 видны `data-slot` и `data-state`,
остальное проверять в живом клиенте (принцип 3).

| Элемент стиля | Пара | Перенос в ZCode |

| Спиннер в шапке, фазная окраска | 65 | статичный глиф — accent, кадры анимации без окраски; после завершения — dim |
| Вывод команды gray, обрезка «… N more lines» | 59 | цвет вывода `--color-foreground-subtlest`, хвост с фейдом |
| Код-ячейка eval, гуттер, intent-титул | 70 | стиль `NodeReplToolCallBlock` по образцу код-ячейки |
| Markdown целиком: ритм, отбивки, «сцена» H1 | 43 | вертикальный ритм `.message-response`, стили блоков |

| Списки: оранжевый маркер, висячий отступ | 43 | `li::marker { color:#fe8019 }`, hanging indent |
| Таблица: квадратный грид дефолтным fg, bold шапка, линии между всеми строками | 12 | `border: 1px solid #d5c4a1`-подобный грид, `th { bold }`, без зебры |
