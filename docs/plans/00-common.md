## Область и принципы

Область — только CSS-инжект zskin поверх `themes/gruvbox.css`: продукт не
меняется, JS не добавляется, подтверждения и квоты не скрываются. Селекторы —
гипотезы (принцип 3); токены `--color-*` стабильнее классов.

## Что уже покрыто темой

Поверхности, текст, границы, brand/status, trajectory, git, usage, terminal,
`--color-markdown-inline-code`, find-highlight, `::selection`, скроллбары,
спиннер (brand), панель статуса.

Не покрыто и всплывает в задачах: diff, progress, `*-surface` семейства
(success/warning/destructive), `interaction-*`, `menu-hover`, `tab-border`,
tooltip-пара, git ignored/descendant/none, idle-task, платный бейдж
плагинов, highspeed-*, primary/primary-foreground, remote-*, палитры
узлов графа.

## Проверка и приёмка

1. **Разведка селекторов.** Статическая — grep по `app.asar`: слоты
   пишутся в двух формах (CSS `data-slot=x`, JSX с backtick), собирать
   одним паттерном, иначе ложные нули. Живая — CDP `Runtime.evaluate` на
   клиенте, поднятом лоадером: перепись data-атрибутов, счётчики
   селекторов, вычисленные стили; светлая схема — атомарная подмена
   классов на `<html>` с откатом. Для сомнительных — временная тема с
   `outline: 1px solid #ff00ff`, затем чистовая правка.
2. **Обе схемы.** Каждая задача проверяется в `theme-zai-dark` и
   `theme-zai-light`; контраст смыслового текста ≥ 4,5:1.
3. **Границы.** Не скрывать и не маскировать подтверждения, квоты,
   индикаторы записи; inline-стили React — только `!important` и с
   комментарием.
4. **Одна задача — один коммит** (или одна секция темы), сообщение
   `feat(theme): <элемент>`; в описании — проверенные селекторы и что
   осталось гипотезой.
5. **После обновления клиента** перегенерировать карту токенов и прогнать
   smoke: карточка, markdown, таблица, дифф, композер, настройки.
